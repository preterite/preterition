{%- comment -%} _includes/strip.html -- the sidebar strip. Three callers: sidebar.html, sidebar-weblog.html, 404.md. TWO DECISIONS MEET HERE and they are not in conflict, though they look it. The strip is drawn as a CSS background rather than an . Pagefind's image metadata comes off src attributes, so a background is invisible to it; attempts to suppress that capture at the indexer all failed, because the lever was never at the indexer but at the element. The strip is nonetheless NOT decoration and is announced. The strips are an identity element with two decades of history, chosen and named by the author; announcing one is the smaller loss against silently withholding from a screen-reader user what every sighted visitor sees. role="img" plus aria-label carries that announcement onto an element that has no alt attribute to give it. The decision survives the change of mechanism intact: what moved is where the name comes from, not whether there is one. The name derives from the filename -- 800witherblister -> witherblister -- so the file is the single source for both the picture and its description. ONE DRAW, HERE, AND THE INLINE STYLE IS DELIBERATE. The picture and the name it announces must be the same strip: a wrong name is worse than no name. That rules out the landing page's mechanism, a noscript rule in head -- an aria-label is an attribute and CSS cannot set one, so the two surfaces would need two draws, and a second `sample` picks a different file. Drawing once in head and reading it here was tried and fails on 404.md, which inlines its own sidebar: Jekyll renders a page's body before its layout, so head has not run and the label comes out empty. Measured, not reasoned -- the build check caught it. The cost is that a reader with scripting ON fetches this strip and then the one initGifRotation draws: one extra GIF, 10-52 KB. Paid knowingly, because the alternative is a screen-reader user hearing the wrong name. Scope: this strip.
