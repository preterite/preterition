{%- comment -%} _includes/listening.html -- the day's rotation. One source, one rule, three consumers: sidebar.html and sidebar-weblog.html draw five tracks, and the landing page's sign-off draws one. It is an include for the reason tagline.html is one: the selection is a rule, and a rule copied into three files is a rule that will disagree with itself. Parameters: count tracks to render. 5 in an aside, 1 in the sign-off. form "track" (the default) renders .music-track divs; "signoff" renders the bare song and artist spans the landing page's own-line expects, with no wrapper of their own. Source is _data/site_songs.csv: title, artist, header row as keys. THE FILE'S ORDER IS LOAD-BEARING AND IT IS NOT THE EXPORT'S. Apple Music writes the list sorted, and that order is the exporter's rather than any fact about listening -- so a positional selection over it renders an alphabetical run, and the run says something false. The committed file is therefore shuffled once, deterministically, and any re-export or addition must be shuffled again before it lands. The failure mode is visible rather than silent: an alphabetical file makes an alphabetically ordered widget. Selection is by the day and not at random, following tagline.html: a build must be reproducible, and `sample` would make two builds of one commit differ. The site rebuilds daily, so the rotation runs on that cadence. THE DAY IS EPOCH DAYS, NOT DAY OF YEAR, and it therefore rolls at midnight UTC -- late afternoon Pacific -- rather than at local midnight. A new set appears with the first build after that rollover, whenever the scheduled run actually lands. Day of year could not carry this rule regardless: it resets at 365 and supplies no cycle counter above the row count. Listening and tagline.html, which still selects on `%j`, rotate independently. THE ASIDE'S FIVE ARE A STRIDE, NOT A GROUP WALK. Spacing five picks n/5 apart is not a walk over the list but a coset of the subgroup of order five, so the set depends only on `start mod n/5`: a hundred rows would yield twenty distinct sets however the file was shuffled. A stride d avoids that when no two of the five collide and the five do not close, which every d coprime to n satisfies; d and n-d give the same set reversed, so the usable range is 1 to n/2. The table below is every odd non-multiple-of-five from 13 to 79 -- the coprime set at n=160 with the small strides dropped, since a stride under 13 draws five near-adjacent rows, harmless over a shuffled file but reading as a block. Twenty-seven strides times 160 starts is 4,320 distinct five-track sets and 11.8 years before one recurs. The table is a rule and not a list: odd, not a multiple of five, 13 to 79. It is correct for n=160 and must be re-derived if the row count changes. THE SIGN-OFF IS THE ASIDE'S FIRST TRACK, by construction: both are songs[start], so count=1 renders exactly what the top of the aside's five renders. Five tracks are visible across the site on a given day, not six. The landing page is a way in, and its nav slices, hexagon and bug all reappear inside, so a song that differed would be the one element asking to be wondered about.
