{%- comment -%} _includes/listening.html -- the day's rotation. One source, one rule, three consumers: sidebar.html and sidebar-weblog.html draw five tracks, and the landing page's sign-off draws one. It is an include for the reason tagline.html is one: the selection is a rule, and a rule copied into three files is a rule that will disagree with itself. Parameters: count tracks to render. 5 in an aside, 1 in the sign-off. form "track" (the default) renders .music-track divs; "signoff" renders the bare song and artist spans the landing page's own-line expects, with no wrapper of their own. link set by the two asides. A track whose song has a page of its own, made by _plugins/tracks.rb, links to that page and shows its running time beside it; a track without one renders as before. The sign-off passes no link. THE PLAY ROW closes an aside's five and is drawn wherever link is set. Each service's name opens a list of the same five songs on that service, and every link in it opens a new window. A song's address on a service is read from _data/listening_links.yml, keyed by the last segment of the song's page address. A song the file does not name for a service takes that service's search address, made from its title and artist, so the row never has a hole. Nothing here is scripted: a list opens on hover and on focus by CSS alone, under the MUSIC WIDGET rules of css/style.css. A song the file names as none for a service is drawn greyed and unlinked, with a boxed X, and its spoken label says the service does not carry it. Source is _data/site_songs.csv: title, artist, header row as keys. THE FILE'S ORDER IS LOAD-BEARING AND IT IS NOT THE EXPORT'S. Apple Music writes the list sorted, and that order is the exporter's rather than any fact about listening -- so a positional selection over it renders an alphabetical run, and the run says something false. The committed file is therefore shuffled once, deterministically, and any re-export or addition must be shuffled again before it lands. The failure mode is visible rather than silent: an alphabetical file makes an alphabetically ordered widget. Selection is by the day and not at random, following tagline.html: a build must be reproducible, and `sample` would make two builds of one commit differ. The site rebuilds daily, so the rotation runs on that cadence. THE DAY IS EPOCH DAYS, NOT DAY OF YEAR, and it therefore rolls at midnight UTC -- late afternoon Pacific -- rather than at local midnight. A new set appears with the first build after that rollover, whenever the scheduled run actually lands. Day of year could not carry this rule regardless: it resets at 365 and supplies no cycle counter above the row count. Listening and tagline.html, which still selects on `%j`, rotate independently. THE ASIDE'S FIVE ARE A STRIDE, NOT A GROUP WALK. Spacing five picks n/5 apart is not a walk over the list but a coset of the subgroup of order five, so the set depends only on `start mod n/5`: a hundred rows would yield twenty distinct sets however the file was shuffled. A stride d avoids that when no two of the five collide and the five do not close, which every d coprime to n satisfies; d and n-d give the same set reversed, so the usable range is 1 to n/2. The table below is the coprime set at n=160 with the small strides dropped -- every odd non-multiple-of-five from 13 to 79 -- since a stride under 13 draws five near-adjacent rows, harmless over a shuffled file but reading as a block. At 290 rows, twenty-seven strides times 290 starts is 7,830 distinct five-track sets and 21.4 years before one recurs. The 48 rows added 2026-10-28 were placed over that full cycle so that two works by one composer, and one pair of songs, never share a day's five. The five rows added 2026-11-10 were placed the same way, the rows already there keeping their order. The forty-three rows added 2026-11-11 were placed the same way, as a bulk seed landing that added songs and no posts. The one row added 2026-11-12 was placed the same way, the rows already there keeping their order, at a growth landing. The table is a rule and not a list: strides from 13 to 79, each coprime to the row count. Odd and not a multiple of five is how that rule came out at 160. At a prime count every stride in range is coprime, so the twenty-seven here stay valid, a subset of what the rule admits. A count that shares a factor with a stride in the table can make that stride draw one track twice in a day's five, as 196 rows does with stride 49, so the table is re-derived whenever the count changes, or the count is kept prime. THE SIGN-OFF IS THE ASIDE'S FIRST TRACK, by construction: both are songs[start], so count=1 renders exactly what the top of the aside's five renders. Five tracks are visible across the site on a given day, not six. The landing page is a way in, and its nav slices, hexagon and bug all reappear inside, so a song that differed would be the one element asking to be wondered about. Sameness here is also what lets the 404's hand-authored five read as deliberate deviation rather than as one more rotation.
