Written as an include for the reason listening.html and tagline.html are: the selection is a rule, and a rule copied into two files is a rule that will disagree with itself. The aside shows five and the sign-off shows that same first one, not a second draw. Parameters: count events to render. 5 in the aside, 1 in the sign-off. form "event" (the default) renders .calendar-event divs; "signoff" renders the bare spans the landing page's own-line expects, with no wrapper of their own. Source is _data/calendar.json, GENERATED at build by _scripts/expand_calendar.py from _calendar/preterite-upcoming.ics. The schema is three pre-formatted strings per event -- day, time, summary -- and that is the contract between the script and this file. All date arithmetic, recurrence expansion and formatting happen in Python: Liquid does none of it, on the same discipline that keeps listening.html to a modulus. time is empty for an all-day event, which renders as a day carrying no time rather than as a zero-length one. Nothing else in the schema is optional. NO SELECTION HAPPENS HERE. Unlike listening.html, which rotates a static list by the day, this file renders the head of a list the script has already ordered by start time. The script writes ten and this renders the first `count` of them, so what a page shows can change without the script being touched. Reporter, not navigator: no outbound link, here or anywhere.
