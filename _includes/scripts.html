{%- comment -%} _includes/scripts.html -- the site's script block, kept apart from _includes/footer.html because an include bundling two responsibilities forces every caller to take both. The landing page needs these scripts and authors its own sign-off, so it takes this file and not the footer. GIFS is emitted below rather than written into main.js. Jekyll's site.static_files is its index of every file it copies through unprocessed, so the strip pool is enumerated from the folder itself at build and no list of filenames is maintained by hand anywhere. main.js derives each strip's alt text from the filename it drew, so the folder is the single source of truth for both halves. taglines.js is generated from _data/taglines.yml at build and is not hand-edited. It carries no load-order constraint of its own: main.js guards on `typeof TAGLINES`, and the markup already holds the build's own pick, so a failure here degrades to the day's tagline rather than to nothing. {%- endcomment -%} {%- comment -%} The search dialog rides here rather than in header.html because this include is exactly the set of pages that load main.js, which is exactly the set that carries a search control.
