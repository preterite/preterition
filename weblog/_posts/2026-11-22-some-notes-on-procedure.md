With a nod to my old editorial gig at [*Kairos*](https://kairos.technorhetoric.net), the following table offers an approach a humanist studying machine writing might take toward building instruments, starting from a [dataset](https://zenodo.org/records/23663062) and its schema.

<!--more-->

I've assigned colors to the steps of the approach on the left, so the corresponding colors on the right show their order and proportion in my recent practice: the left colors code the wish, the right colors track the work.

{% include tool-making-sheet.html %}

|   | Steps |   | Notes |
|---|---|---|---|
| 1 | **Decide what the instrument measures and what counts as zero.** a falsifiable claim; a null to set against the claim; the empty case, specified as a condition the data can run |   | The empty condition is a dataset run with nothing carried forward, passed through the same arithmetic as every other and read on the same face. Every reading is a departure from the empty condition. |
| 2 | **List every mark the instrument will show; find each mark's field in the dataset schema.** identifiers, counts, positions, flags; the labels the data uses; any data selection will predetermine some choices |   |   |
| 3 | **Outline the path before building: steps, reviews, dependencies.** each item to release, in order; what each waits on; what checks it |   |   |
| 4 | **Determine what difference the instrument displays, and in what form.** the departure to count as evidence, named before the data is consulted; a quantity on a displayed scale; one family of curves, exponent selected |   | A departure has a size and a power; they are different readings of the same run. Choosing the energy of a departure over its distance makes a claim prior to any value's display. |
| 5 | **Locate the difference in the data.** a census of every run; which fields feed which sums; prioritize the *where* before the *what* |   | I stumbled in seeking the point or moment in playing back a run from the dataset where a word's meaning should change. The difference happened at no point. It gathered as a smudge across the arc from one corpus to the next, in the shape of the room, with room understood in the acoustic sense as a shape that conditions what sounds. |
| 6 | **Write the arithmetic as a repeatable model and prove it against the dataset's check values.** reproducible results generated by a script; published baselines reproduced by assertion; what the numbers can and cannot show |   | An early test scaled its noise along with the signal and resembled a finding. The clean one reproduced every baseline; resampling then found no ordering that held more than a third of the time. The arithmetic yielded a geometry; the face shows the geometry and leaves order unranked. |
| 7 | **Fix the scale and the zero; query the dataset's documentation for any bound not given in the data.** one range for every run; limits displayed where sought; each gap traced to a source or a query |   | Autoscaling hides a limit by moving it. A declared top, marked, with a clip indicator for anything past, shows when a run leaves the scale, which is a reading. |
| 8 | **Decide what every control does, in every state, and lay out the instrument's face on real data.** *on, off, ready, unavailable*; what presses change in each; tests on recorded runs rather than placeholder data |   |   |
| 9 | **Build the working face plain at every size, joined to shared components, with a test that can fail.** wireframe first to user scales; link elements common to all instruments; build checks to progress from red to green |   |   |
| 10 | **Design the appearance on studies laid over the plain working face.** position and size before color, never color alone; contrast only where the data differs; *[the human eye diffs before it reads](https://youtu.be/3eZ15VplE3o?t=59)*. |   |   |
| 11 | **Build each finished part into the face before the next is drawn, then incorporate supplemental media.** proven in place on the page; the study retired once its element lands; synthesizing review on live local copy last |   |   |
| 12 | **Take every test to zero; then document, trim, package, and release.** each failure fixed and struck; ship nothing unused by the page; the bundle runs as standalone |   |   |

A humanist writing researcher who crafts instruments that use language models as a control group without a psyche can pose a question: which aspects of writing are structural results of generating sequential prose under constraint?

The answers, one hopes, indicate a way to invert the question: how can we  inquire more precisely into the remainder's irreducibly human aspects of writing?
