{%- comment -%} data-pagefind-body scopes the search index to the main column. Pagefind indexes from by default, which on this site puts the strip's alt text, Listening, the tagline and the footer into the index on every page, so one track name matches every page that has a sidebar. The attribute also decides membership and not only extent: once it appears anywhere on the site, a page without it is not indexed at all. That is how protected-inquiries stays out -- contact-page-spec.md, a decision making it easier to discover has misread the page -- how the 404 stays out, and how the landing page stays out (RULED 2026-08-25, Michael): the wall's glosses are each target page's own description, already indexed on the target, so a hit should land on the page and not on the page that links to it. The weblog index is out for the same reason a level down, which is what the ignore on .blog-card does in weblog.html. Membership is a criterion, not a count: one page per source taking this layout, plus one per post. Content scoping and metadata capture are not the same mechanism, and nothing in Pagefind 1.5.2 reaches the second. Pagefind derives image metadata from src attributes, and while the strip was an it was the first image in the document on every page whose main column has none -- so Pagefind took it as the page's default image metadata, and it indexes metadata VALUES as searchable text, which is how a query for "alarm" came to return seven pages. Measured 2026-08-25 against a local index: data-pagefind-ignore on the aside, exclude_selectors in a config file, and the same as a CLI flag each produced a byte-identical index, and the comma form of data-pagefind-meta sets no second key -- it extends the first key's literal value. The lever was never at the indexer. No points at a strip anywhere in the built site, so no page carries image metadata and the dialog has none to render. data-pagefind-meta supplies the result title.
